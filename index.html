Guía de transición · edición 2026

De Windows a Fedora con KDE Plasma

Linux no es Windows con otra interfaz. Cambia el modelo de responsabilidades, la forma de instalar software y el lugar donde vive la configuración. Esta guía explica ese cambio desde cero y termina con un entorno de desarrollo productivo sobre Fedora y Plasma 6.

Fedora 44+ KDE Plasma 6 DNF5 Wayland Btrfs SELinux Podman
Sobre las versiones

Fedora publica una versión nueva cada seis meses y Plasma evoluciona al mismo ritmo. Los números concretos cambian; los conceptos, rutas y comandos de esta guía se mantienen estables. Comprueba tu versión con cat /etc/fedora-release.

Para quién es

Para quien programa y viene de Windows: conoce la terminal, los entornos de desarrollo y los contenedores, pero nunca administró un sistema Linux de escritorio.

Qué no es

No es un manual de Ubuntu ni una lista de trucos. Es el mapa mental que hace que el resto de la documentación de Linux tenga sentido.

Cómo leerla

En orden la primera vez. Después, usa el índice lateral o el buscador para volver a una sección concreta. Cada capítulo es autónomo.

01 Windows → Linux

El primer obstáculo no es técnico: es esperar que Linux se comporte como Windows. Este capítulo describe las diferencias estructurales que explican casi todas las demás.

1.1 El cambio de modelo mental

En Windows, el sistema operativo y la interfaz forman una unidad comercial: Explorer, el registro, Windows Update y el instalador de turno son parte del mismo producto. En Linux, el núcleo, las utilidades, el gestor de paquetes y el escritorio son proyectos separados que una distribución ensambla. Esa separación es la que permite cambiar de escritorio sin reinstalar el sistema, o actualizar el kernel sin tocar tus aplicaciones.

La idea clave

El escritorio no es el sistema. Si Plasma se rompe, el sistema sigue funcionando y puedes entrar por una TTY o restaurar la configuración. Si el sistema se rompe, el escritorio no existe, pero tus datos siguen en /home.

1.2 Kernel, userland y distribución

Tres palabras que se usan como sinónimos y no lo son. El kernel es el programa que habla con el hardware: planifica procesos, gestiona memoria, expone el sistema de archivos virtual y atiende las llamadas al sistema. El userland es todo lo que corre por encima: glibc, bash, coreutils, systemd. La distribución empaqueta kernel + userland + repositorios + instalador + políticas y decide los valores por defecto.

Errores clásicos

chmod 777 no arregla permisos: los desactiva. sudo su abre una shell root permanente donde un error de tipeo es irreversible. Y ejecutar aplicaciones gráficas con sudo puede dejar archivos de configuración con dueño root en tu home.

sudo eleva un comando concreto, pide tu contraseña y registra la operación. En el escritorio, polkit cumple un papel similar: una aplicación sin privilegios pide autorización al servicio del sistema mediante un diálogo, sin que tú tengas que abrir una terminal.

1.5 Procesos, servicios y systemd

Cada programa en ejecución es un proceso con un PID y un proceso padre. Los procesos se comunican con señales: SIGTERM pide terminar, SIGKILL obliga, SIGHUP indica recargar configuración. Los servicios del sistema los gestiona systemd, que además monta sistemas de archivos, configura la red, arranca la sesión gráfica y recoge los logs.

1.6 Todo es un archivo

La frase es una simplificación, pero describe una idea potente: dispositivos, información del kernel, sockets y tuberías se exponen mediante una interfaz común de lectura y escritura. Eso permite usar las mismas herramientas (cat, grep, less) sobre cosas que en Windows requerirían una API específica.

Compatibilidad

Un binario ELF no se ejecuta en Windows y uno PE no se ejecuta en Linux. Wine y Proton implementan las APIs de Windows para ejecutar juegos y algunas aplicaciones; WSL hace lo contrario: expone un kernel Linux dentro de Windows. Ninguna de las dos cosas convierte a Linux en Windows.

Cuidado con ldd

ldd puede ejecutar código del binario que analiza. No lo uses sobre ejecutables que no confías; en ese caso, readelf -d o objdump -p son más seguros.

02 Fedora

Fedora es una distribución patrocinada por Red Hat, comunitaria en su gobernanza y upstream de RHEL. Su personalidad: tecnología reciente con valores por defecto conservadores y buena integración.

2.1 Qué es Fedora

Fedora es el laboratorio donde Red Hat y la comunidad prueban tecnologías que más tarde llegan a RHEL: systemd, Wayland, PipeWire, SELinux, Btrfs, cgroups v2, DNF5. Eso la coloca en un punto intermedio entre Arch (rolling release, tú lo ensamblas) y Debian estable (software antiguo a cambio de estabilidad). Fedora es leading edge, no bleeding edge.

La relación con RHEL importa en ambos sentidos. Fedora recibe recursos e infraestructura; RHEL recibe código probado. CentOS Stream es el puente: la rama pública donde se estabiliza lo que Fedora ya adoptó.

Por qué Fedora para un desarrollador

Toolchains recientes, kernel nuevo (buen soporte de hardware), SELinux activo por defecto, contenedores de primera clase con Podman y una comunidad upstream que documenta lo que mantiene. Si algo funciona en Fedora, probablemente funcione en RHEL y en la nube.

2.2 Ediciones, spins y escritorios atómicos

Fedora no es un solo producto. Hay ediciones oficiales con soporte de primer nivel, spins comunitarios con otro escritorio y variantes atómicas con el sistema de solo lectura. Para un escritorio de desarrollo, la elección relevante es Fedora KDE Plasma Desktop, que desde Fedora 42 es una edición oficial y no solo un spin.

Cada actualización crea una nueva generación; si algo falla, se arranca la anterior desde GRUB. Las aplicaciones de usuario van por Flatpak o contenedores. La contrapartida es menos flexibilidad para modificar el sistema y una curva de aprendizaje adicional.

Recomendación

Si vienes de Windows y quieres aprender Linux de forma directa, empieza con la edición tradicional. Los escritorios atómicos son excelentes, pero añaden una capa de indirección que conviene entender después.

2.3 Ciclo de versiones y actualizaciones

Fedora publica una versión nueva aproximadamente cada seis meses, en abril y octubre. Cada versión recibe actualizaciones durante unos 13 meses: mientras sea la actual y durante el ciclo de la siguiente. No es un rolling release, pero el kernel y los drivers avanzan dentro de cada versión.

# Actualizar la versión actual (parches y kernels)
$ sudo dnf upgrade --refresh

# Saltar a la siguiente release
$ sudo dnf system-upgrade download --releasever=45
$ sudo dnf system-upgrade reboot

El salto de versión se hace con system-upgrade: descarga todos los paquetes, los aplica en un entorno offline durante el reinicio y conserva el kernel anterior. Si el subcomando no existe, falta el plugin correspondiente a tu versión de DNF (dnf-plugin-system-upgrade o dnf5-plugin-system-upgrade).

Antes de saltar de versión

Haz una copia de seguridad, lee las notas de la release y actualiza primero la versión actual. No saltes más de una release a la vez: Fedora está pensada para upgrades incrementales.

2.4 Filosofía y valores por defecto

Fedora sigue una política upstream-first: los parches se envían a los proyectos originales en lugar de acumularse en la distribución. Eso reduce la deuda técnica y explica por qué las versiones de software son recientes. También implica que Fedora cambia de tecnología cuando el upstream lo hace, a veces antes que otras distribuciones.

03 Gestores de paquetes

Aquí está la diferencia práctica más grande con Windows. Un gestor de paquetes no es una tienda de aplicaciones: es un sistema de resolución de dependencias, verificación criptográfica y transacciones atómicas.

3.1 Anatomía de un paquete y un repositorio

Un paquete RPM contiene metadatos (nombre, versión, release, arquitectura, licencia, dependencias, scripts de instalación) y un payload comprimido con los archivos. Un repositorio es un servidor HTTP con esos paquetes, índices XML y una clave GPG. DNF descarga los índices, resuelve el grafo de dependencias con un solver SAT y ejecuta una transacción. 

repositorio

  ├─ repodata/*.xml.gz         índices comprimidos
  ├─ Packages/*.rpm            payloads
  └─ repomd.xml + firma GPG    integridad del índice

La regla es no mezclar capas. Instalar una biblioteca de Python con sudo pip puede sobrescribir archivos que pertenecen a RPM y romper el gestor de paquetes. Si el paquete existe en los repositorios, se instala con DNF; si es de un proyecto, va en un entorno virtual.

04 Terminal esencial

Puedes usar Fedora sin abrir una terminal, pero como ingeniero de software vas a vivir en ella. No hace falta memorizar cientos de comandos: basta con entender el shell, el PATH, los flujos y las cuatro herramientas que resuelven el 90 % del trabajo diario.

4.1 Shell, PATH y entorno

El shell es el programa que interpreta tus comandos. En Fedora, bash es el valor por defecto; zsh y fish están disponibles si prefieres otra experiencia interactiva. El shell no es la terminal: la terminal es la ventana; el shell es el intérprete que corre dentro.

PATH es una lista de directorios separados por : donde el shell busca ejecutables, en orden. Si un comando «no existe» pero el archivo está ahí, casi siempre es un problema de PATH o del bit de ejecución. 

# Dónde está y qué es cada comando
$ command -v code
/usr/bin/code
$ type -a python3
python3 is /usr/bin/python3

# Variables de entorno
$ echo $PATH
$ printenv | sort | head
$ export EDITOR="kate -b"
$ export PATH="$HOME/.local/bin:$PATH"

# Archivos de configuración del shell
$ ls -la ~/.bashrc ~/.bash_profile ~/.profile

Para tu usuario, edita ~/.bashrc (shell interactivo) y ~/.bash_profile (login). Para todo el sistema, /etc/profile.d/*.sh. Evita editar /etc/profile directamente: las actualizaciones pueden sobrescribirlo. 

# ~/.bashrc — un punto de partida razonable

export EDITOR="kate -b"
export PAGER="less -FRX"

# Aplicar cambios sin cerrar la sesión
$ source ~/.bashrc
Login vs interactivo

Una shell de login lee ~/.bash_profile; una interactiva no login lee ~/.bashrc. Las terminales gráficas suelen abrir shells no login, mientras que una TTY o ssh abre una de login. Si una variable «desaparece» según cómo entres, es por esta diferencia.

4.3 Permisos en práctica

Ya viste los bits en el capítulo 1. En el día a día usarás la forma simbólica para cambios puntuales y la octal para valores completos. umask define los permisos que se restan por defecto a los archivos nuevos.

$ chmod g-w archivo.txt
$ chmod o-r secreto.txt
$ chmod a+r documentacion.pdf

# Octal: lectura=4, escritura=2, ejecución=1
$ chmod 755 script.sh
$ chmod 600 ~/.ssh/id_ed25519

$ sudo chown jose:devs proyecto/
$ sudo chgrp devs proyecto/

$ umask 027

La redirección no hereda sudo

06 Instalación y primer arranque

La instalación de Fedora es rápida; las decisiones que importan se toman antes: cómo convivir con Windows, cómo particionar y qué hacer con Secure Boot. Este capítulo asume que ya tienes el equipo y quieres un escritorio utilizable, no una instalación de laboratorio.

6.1 ISO, verificación y Secure Boot

Descarga la imagen de Fedora KDE Plasma Desktop desde el sitio oficial. Verifica siempre la suma SHA-256 y la firma GPG: una ISO corrupta produce fallos difíciles de diagnosticar y una ISO manipulada es un riesgo de seguridad. 

# Verificar integridad
$ sha256sum Fedora-KDE-Desktop-*.iso
$ curl -LO https://fedoraproject.org/fedora.gpg
$ gpg --verify Fedora-KDE-Desktop-*-CHECKSUM
$ sha256sum -c Fedora-KDE-Desktop-*-CHECKSUM

# Escribir a un USB (¡verifica el dispositivo con lsblk!)
$ lsblk
$ sudo dd if=Fedora-KDE-Desktop-*.iso of=/dev/sdX bs=4M status=progress oflag=sync conv=fsync
dd no perdona

of=/dev/sdX debe ser el dispositivo completo, no una partición (/dev/sdX1). Si te equivocas, borras el disco. Fedora Media Writer hace lo mismo con una interfaz y es la opción recomendada si no tienes prisa.

Fedora firma su shim, GRUB y el kernel, así que arranca con Secure Boot activo sin intervención. El problema aparece con módulos de terceros, como el driver NVIDIA propietario: el módulo no está firmado por Microsoft y el firmware lo rechaza. La solución es MOK (Machine Owner Key): importas la clave pública de akmods y la enrollas una vez en el arranque. 

# Tras instalar akmod-nvidia, importar la clave y reiniciar
$ sudo mokutil --import /etc/pki/akmods/certs/public_key.der
$ sudo reboot

# En el menú MOK: Enroll MOK → Continue → Yes → contraseña → reboot
$ mokutil --list-enrolled | grep -i akmod

Antes de tocar particiones, decide el escenario. El dual boot es cómodo pero comparte el disco y el gestor de arranque; una máquina virtual es reversible pero más lenta en gráficos; un disco dedicado es la opción más limpia si puedes permitírtelo.

  3. Reduce la partición NTFS desde Administración de discos y deja espacio sin asignar.
  4. Arranca el USB en UEFI, instala Fedora en el espacio libre y deja que use la ESP existente.
  5. Comprueba que GRUB detecta Windows. Si no, regenera la configuración.

BitLocker

Si Windows tiene BitLocker, suspéndelo antes de modificar particiones. Un cambio en la tabla de particiones puede forzar la recuperación y, sin la clave, perderás el acceso. Guarda la clave de recuperación fuera del equipo.

6.3 Particionado, Btrfs y cifrado

En UEFI, Fedora necesita una partición EFI (FAT32) y una raíz. El instalador propone un esquema con Btrfs, subvolúmenes root y home, /boot en ext4 y zram como swap comprimida en RAM. Es un buen punto de partida.

HomeResto (opcional)Btrfs o ext4/home
Swapzram por defecto; swapfile si hibernas——

Btrfs aporta snapshots, compresión transparente y subvolúmenes. Fedora no activa snapshots automáticos por defecto; si quieres ese flujo, instala snapper o btrfs-assistant y configura una política. La compresión zstd se puede añadir en /etc/fstab con compress=zstd:1.

$ findmnt --real
$ sudo btrfs subvolume list /
$ sudo btrfs filesystem usage /

# Cifrado LUKS2 y desbloqueo con TPM2
$ sudo cryptsetup luksDump /dev/nvme0n1p3
$ sudo systemd-cryptenroll --tpm2-device=auto --tpm2-pcrs=7 /dev/nvme0n1p3

# Snapshot manual de la raíz (si existe el subvolumen)
$ sudo btrfs subvolume snapshot -r / /.snapshots/root-$(date +%F)
Cifrado: decide antes

Cifrar la raíz y el home con LUKS2 protege los datos si pierdes el equipo, pero complica la recuperación y el desbloqueo remoto. Con TPM2 puedes desbloquear automáticamente al arrancar; sin TPM, necesitarás la contraseña en cada inicio.

7.4 Git, SSH y GPG

La configuración de Git es idéntica a la de Windows; cambian el editor, el helper de credenciales y la integración con el llavero. En Plasma, KWallet puede actuar como almacén de secretos, y libsecret conecta Git con él. 

# Identidad y valores por defecto
$ git config --global user.name "Tu Nombre"
$ git config --global user.email "tu@correo.dev"
$ git config --global init.defaultBranch main
$ git config --global core.editor "kate -b"
$ git config --global pull.rebase false
$ git config --global credential.helper libsecret

# Claves SSH
$ ssh-keygen -t ed25519 -C "tu@correo.dev"

$ ssh -T git@github.com

Para firmar commits, SSH es suficiente en GitHub y GitLab y reutiliza la clave que ya tienes. GPG sigue siendo necesario si tu organización lo exige o si firmas correo y tags con la misma identidad.

7.5 Virtualización con KVM

KVM es la virtualización nativa de Linux: el kernel actúa como hipervisor y QEMU emula el hardware. libvirt gestiona las máquinas y virt-manager ofrece una interfaz gráfica. El rendimiento es muy superior a VirtualBox para cargas de trabajo serias.

08 Seguridad y mantenimiento

Fedora viene con SELinux enforcing, firewalld activo y actualizaciones firmadas. La seguridad no consiste en añadir capas, sino en entender las que ya están y no desactivarlas por comodidad.

8.1 SELinux y firewalld

SELinux etiqueta procesos y archivos con contextos y aplica una política: un proceso solo accede a lo que su dominio permite, aunque los permisos POSIX digan otra cosa. Es una capa de control de acceso obligatorio (MAC) que complementa los bits rwx. firewalld gestiona el cortafuegos por zonas y servicios, con cambios en caliente.

09 Problemas comunes

Una selección de los tropiezos habituales en Fedora KDE, con el diagnóstico y la solución. Si tu caso no está aquí, el capítulo 8 tiene las herramientas para encontrarlo.

Pantalla negra o resolución incorrecta tras actualizar NVIDIA

Lo más probable es que el módulo no se haya recompilado contra el kernel nuevo o que Secure Boot haya rechazado la firma. Arranca el kernel anterior desde GRUB y comprueba: 

$ uname -r
$ modinfo -F version nvidia
$ dnf list --installed | grep -E 'nvidia|akmod'
$ sudo akmods --force
$ sudo dracut --force
$ sudo reboot

Si el módulo no aparece, revisa journalctl -b -p err y dmesg | grep -i nvidia. Con Secure Boot activo, verifica que la clave de akmods esté enrollada con mokutil --list-enrolled.

No hay audio o suena por el dispositivo equivocado

PipeWire sustituyó a PulseAudio. Comprueba el grafo, el perfil y la salida por defecto: 

$ wpctl status
$ wpctl set-default <id>
$ systemctl --user restart wireplumber
$ pavucontrol

Si el dispositivo no aparece, mira dmesg -T | grep -i audio y asegúrate de que el firmware sof-firmware esté instalado en portátiles recientes.

Wi-Fi lento, se desconecta o no aparece

Empieza por NetworkManager y el driver, no por reinstalar: 

$ nmcli device status
$ nmcli connection show
$ nmcli device wifi list
$ dmesg -T | grep -iE 'iwlwifi|ath|rtw|firmware'
$ sudo dnf install linux-firmware

En algunos chips Intel, el ahorro de energía causa desconexiones. Como prueba temporal: sudo iw dev wlan0 set power_save off. Si funciona, hazlo permanente con una regla de NetworkManager o un módulo de configuración.

La impresora no aparece o no imprime

CUPS se activa por socket. Comprueba el servicio, la cola y el descubrimiento IPP: 

$ systemctl status cups
$ lpstat -t
$ system-config-printer
$ sudo firewall-cmd --list-all

Para impresoras modernas, usa driverless IPP con la URI ipp://direccion/ipp/print. Evita drivers propietarios si el modelo soporta AirPrint/IPP Everywhere.

«externally-managed-environment» al usar pip

Es PEP 668: Fedora protege los paquetes de Python del sistema. No uses --break-system-packages. Crea un entorno virtual o instala la herramienta con pipx: 

$ python3 -m venv .venv
$ source .venv/bin/activate
$ pip install -r requirements.txt
$ deactivate

$ pipx install poetry
$ pipx install ruff
Una app Flatpak no ve mis archivos o no puede guardar

El sandbox solo concede lo declarado. Revisa permisos y añade el directorio concreto, no el home entero si puedes evitarlo: 

$ flatpak permissions
$ flatpak override --user --filesystem=~/Proyectos org.example.App
$ flatpak override --user --filesystem=xdg-download org.example.App
$ flatpak override --user --nofilesystem=home org.example.App

Flatseal ofrece la misma funcionalidad con interfaz gráfica y muestra qué portals usa cada aplicación.

Compartir pantalla, OBS o Discord no funcionan en Wayland

La captura pasa por xdg-desktop-portal-kde y PipeWire. Verifica que ambos estén activos y que la app use el portal: 

$ systemctl --user status xdg-desktop-portal-kde
$ systemctl --user restart xdg-desktop-portal-kde
$ flatpak permissions

En Electron/Chromium, algunas apps necesitan --ozone-platform-hint=auto o --enable-features=WebRTCPipeWireCapturer. Si nada funciona, prueba la sesión X11 como último recurso.

Windows no aparece en GRUB o el reloj está desincronizado

Fedora puede no detectar Windows si os-prober está desactivado. Instálalo, habilítalo y regenera GRUB: 

$ sudo dnf install os-prober
$ echo 'GRUB_DISABLE_OS_PROBER=false' | sudo tee -a /etc/default/grub
$ sudo grub2-mkconfig -o /boot/grub2/grub.cfg
$ sudo timedatectl set-local-rtc 0

El reloj se debe a que Windows usa hora local y Linux UTC. La solución recomendada es hacer que Windows use UTC (clave RealTimeIsUniversal), no configurar Linux en hora local.

Una actualización se interrumpió y el sistema quedó inconsistente

No reinstales todavía. DNF guarda transacciones y RPM puede verificar archivos: 

$ sudo dnf history
$ sudo dnf history undo <id>
$ sudo dnf distro-sync --refresh
$ sudo rpm -Va --nofiles --nodigest
$ sudo dnf repoquery --unsatisfied

Si el sistema no arranca, entra por una TTY (Ctrl+Alt+F3) o desde un live USB con chroot. Un snapshot previo es la vía más rápida.

¿Necesito antivirus?

No hay un antivirus residente equivalente a Windows Defender, y no es la prioridad. Las amenazas reales en un escritorio Linux suelen venir de extensiones de navegador, paquetes de npm/pip maliciosos, repositorios de terceros y contraseñas reutilizadas. Mantén el sistema actualizado, instala desde fuentes oficiales y revisa permisos de Flatpak.

Si intercambias archivos con Windows, puedes instalar clamav para escaneos puntuales, pero no sustituye la higiene operativa.

¿Puedo usar Office, Photoshop o Adobe?

No de forma nativa. Alternativas: LibreOffice o OnlyOffice para documentos, GIMP y Krita para imagen, Inkscape para vector, DaVinci Resolve para vídeo. Para apps Windows concretas: Bottles/Wine, una VM con KVM, o una suscripción web cuando exista. Adobe CC no tiene soporte oficial en Linux.
